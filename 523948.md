# YSLMitao Resource Aggregator

YSLMitao Resource Aggregator is a curated technical index and navigation system designed for developers, researchers, and content distributors who require structured access to specialized digital media resources. The project functions as a metadata hub that organizes, categorizes, and provides uniform access points to a defined set of domain-specific content collections, with emphasis on availability, format consistency, and retrieval efficiency.

The target audience includes automated workflow engineers, data curation specialists, and integration developers who need programmatic or human-readable entry points to resource groups that follow predictable naming conventions and availability patterns. The aggregator does not host any content directly; it serves exclusively as a logical index layer that maps human-readable identifiers to resource locations, enabling consistent access control, monitoring, and failover handling across the referenced endpoints.

## 功能概览

- **Unified Resource Indexing** - Provides a single consistent entry table that maps all available resource domains to their respective access points, eliminating the need for manual bookmark management.

- **Availability Health Checking** - Implements passive and active monitoring against each indexed domain to track response times, HTTP status codes, and SSL certificate validity periods.

- **Categorized Content Grouping** - Organizes the aggregated resources into logical subcategories based on naming patterns, content type indications, and format specifications for rapid filtering.

- **Metadata Extraction Pipeline** - Automatically parses and extracts structured metadata from each resource endpoint response, including content-type headers, content-length, and last-modified timestamps.

- **Rate-Limited Access Proxy** - Offers an optional lightweight proxy layer that applies configurable request throttling to prevent overwhelming any single upstream resource.

- **Exportable Inventory Format** - Supports exporting the full index in multiple machine-readable formats including JSON, YAML, and CSV for downstream integration.

- **Delta Change Detection** - Tracks changes in resource availability and response characteristics over time, generating diff reports for auditing purposes.

- **Custom Tagging System** - Allows operators to attach arbitrary key-value tags to each resource entry for personalized classification and query filtering.

## 应用场景

- **Automated Media Pipeline Integration** - Development teams building automated retrieval workflows can consume the aggregator's structured index to dynamically route requests to available resources without hardcoding domain names, enabling graceful degradation when individual endpoints become temporarily unreachable.

- **Content Distribution Network Monitoring** - Site reliability engineers can deploy the aggregator's health checking module to continuously validate the operational status of all referenced resource domains, receiving alerts when any endpoint deviates from expected response patterns.

- **Data Provenance and Audit Trails** - Compliance officers and data governance personnel utilize the aggregator's delta detection and metadata extraction features to maintain historical records of resource availability and content changes, supporting internal audit requirements.

- **Research Dataset Construction** - Academic researchers and data scientists leverage the categorized grouping functionality to filter resources by format or content indication, constructing curated datasets for analysis while maintaining traceability back to original sources.

- **Integration Testing Sandbox** - Quality assurance teams employ the rate-limited proxy mode to simulate various resource response conditions during integration testing, validating application behavior under network degradation scenarios without affecting production resources.

## 快速开始

```bash
# Clone the repository from the official source
git clone https://github.com/yslmitaoproject/aggregator.git
cd aggregator

# Install all required dependencies using pip for Python-based deployment
pip install -r requirements.txt

# Initialize the local index database and configuration files
python scripts/init_db.py --config config/default.yaml

# Run the aggregator service with default settings on port 8080
python main.py --host 0.0.0.0 --port 8080 --mode production
```

After executing the above commands, the aggregator service will be accessible at <code>http://localhost:8080</code>. The API root endpoint returns the full resource index in JSON format. To perform a health check on all indexed resources, issue a POST request to <code>/api/v1/health/check</code>. The system logs are written to <code>./logs/aggregator.log</code> by default with rotation configured for 30-day retention.

## 贡献指南

1. **Fork 仓库并创建特性分支** - 从主仓库 fork 到个人账户，然后基于 <code>develop</code> 分支创建 <code>feature/your-feature-name</code> 分支，确保分支名称简短描述所添加的功能或修复的问题。

2. **编写或更新单元测试** - 所有新增代码必须在 <code>tests/unit/</code> 目录下具备对应的测试用例，测试覆盖率不得低于 85%。运行 <code>pytest --cov=core --cov=api</code> 验证本地测试通过。

3. **遵循代码风格规范** - 使用 Black 格式化器（行宽 100 字符）和 isort 进行导入排序，同时通过 flake8 检查代码质量。提交前执行 <code>make lint</code> 确保无风格警告。

4. **更新相关文档** - 若修改了配置项、API 接口或数据库模式，必须同步更新 <code>docs/</code> 目录下对应的文档文件。新增功能需在 <code>docs/api_reference.md</code> 中添加接口说明。

5. **发起 Pull Request 并描述变更** - 推送分支到个人远程仓库后，向主仓库的 <code>develop</code> 分支发起 PR。PR 描述须包含变更动机、实现方式、测试结果和影响范围，至少两名项目维护者审核后方可合并。

## 常见问题

**问：聚合器本身是否缓存或存储来自上游资源的任何实际内容？**

答：聚合器不缓存、不存储、不转发任何来自上游资源的媒体内容或文件数据。它仅存储资源的元数据，包括域名、响应头信息、时间戳和可用性状态。所有内容请求均通过 302 重定向或直接返回上游 URL，由客户端自行发起实际内容获取。聚合器的存储层（SQLite 和 Redis）仅保存索引记录、健康检查日志和配置参数，不涉及任何版权保护内容的持久化。

**问：当某个上游资源返回 5xx 错误或超时时，聚合器如何处理？**

答：聚合器的健康检查模块维护每个资源的连续失败计数器。当连续失败次数达到配置阈值（默认 3 次）时，该资源会被标记为 <code>unhealthy</code> 状态并从主动轮询队列中临时移除，进入退避冷却期（冷却时长呈指数增长，初始 60 秒）。冷却期结束后，系统会尝试一次探测请求，若成功则恢复健康状态并重新加入轮询队列。在健康检查间隙，API 请求仍可查询到该资源记录，但响应中会附带 <code>status: degraded</code> 字段供客户端决定是否使用该地址。

**问：是否可以自定义资源分组和标签，或者动态添加新的资源地址？**

**答：** 支持运行时动态添加和分组资源。管理员可通过 POST <code>/api/v1/resources</code> 端点提交新资源地址、分组名称和自定义标签列表，系统会自动验证域名格式并执行初始健康检查。所有自定义分组和标签均存储在数据库中并支持按标签查询过滤。此外，管理员可通过 YAML 配置文件批量预置分组规则，启动时自动加载。删除或归档资源同样通过 API 完成，已归档条目会保留在历史表中但不再参与健康检查轮询。
