# YSLMitao Resource Index

YSLMitao is a curated technical resource aggregation and navigation system designed for developers, researchers, and content archivists who require structured access to distributed media metadata and indexed content references. The project addresses the fundamental challenge of managing large-scale external resource links that are frequently updated, categorized by content type, and require consistent availability monitoring. Rather than building yet another search engine or crawler, YSLMitao provides a lightweight, maintainable index layer that sits above existing content sources, offering deterministic URL routing, category tagging, and status tracking through a simple command-line interface and static site generation pipeline.

The primary target users are technical operators who maintain curated link collections, data journalists tracking online media footprints, and archival researchers who need reproducible snapshots of resource availability over time. The project does not host, proxy, or transform any external content; it strictly maintains a verifiable manifest of resource locations with optional metadata annotations. By separating the index logic from the content itself, YSLMitao enables collaborative maintenance of large resource lists without requiring centralized database infrastructure, making it suitable for both individual power users and small team workflows.

## 功能概览

- **Deterministic Resource Manifest** – Maintains a YAML-based master manifest that maps logical resource categories to physical URL endpoints, with support for version tagging and expiration timestamps.

- **Availability Health Check** – Includes a built-in verification script that performs HEAD requests against all indexed URLs, reporting HTTP status codes, response times, and TLS certificate validity in a structured JSON output.

- **Category-Based Tagging System** – Assigns each resource to one or more predefined categories (e.g., video, image, metadata, archive) with custom tag schemas that can be extended via configuration files without code changes.

- **Static Site Generator Mode** – Transforms the resource manifest into a self-contained HTML dashboard with searchable tables, filterable category views, and a live status badge system for quick visual assessment.

- **Command-Line Query Interface** – Provides a lightweight CLI tool that supports regex-based filtering, batch export to CSV, and differential comparison between two manifest versions to detect added, removed, or changed URLs.

- **Scheduled Refresh Daemon** – Offers an optional systemd timer integration that periodically updates the health status cache and generates change logs, reducing manual verification overhead for large collections.

- **Import/Export Adapters** – Supports importing resource lists from plain text files, CSV, and common bookmark export formats (Netscape HTML), with export to JSON, YAML, and Markdown table formats for documentation integration.

- **Minimal Dependency Footprint** – Written entirely in POSIX-compliant shell scripts and GNU Make, with optional Python helpers for advanced filtering; runs on any Linux distribution, macOS, or Windows WSL2 environment without container overhead.

## 应用场景

- **Curated Media Metadata Indexing** – A research team tracking online video metadata sources can use YSLMitao to maintain a categorized list of reference URLs, with daily health checks ensuring that broken links are quickly identified and reported through the dashboard. The tag system allows sorting by resolution, format, or content type, making it easy to generate periodic reports for project stakeholders.

- **Automated Resource Lifecycle Management** – An archive operator managing a large set of external references can leverage the differential comparison feature to detect when upstream resources change their URL structure or become unavailable. This enables proactive updating of internal documentation and alerting workflows without manual page-by-page inspection.

- **Collaborative Link Database Maintenance** – A small development team working on open data projects can share the manifest file via version control, with each member contributing new resource entries through pull requests. The built-in validation hooks prevent malformed URLs and duplicate entries, ensuring that the manifest remains consistent and deployable at all times.

- **Offline Documentation Preparation** – A technical writer preparing offline documentation bundles can use the static site generator to produce a self-contained resource reference page that does not require external CSS or JavaScript CDN dependencies, making it suitable for air-gapped environments or long-term archival storage.

- **Compliance and Auditing Trail** – A compliance officer tracking third-party content sources can configure the daemon to log every change in the manifest along with timestamps and contributor identifiers (via Git commit metadata), producing an auditable history of resource associations that meets internal governance requirements.

## 快速开始

Clone the repository, install the minimal dependencies, and run the initial manifest validation:

```bash
git clone https://github.com/yslmitao/resource-index.git
cd resource-index
make setup
make validate
make build
make serve
```

The above commands perform the following steps: clone the project source, install required system utilities (curl, jq, sed, GNU Make), validate the structure of the default manifest file, generate the static HTML dashboard into the `_site` directory, and start a local HTTP server on port 8080 for preview. For production deployments, the generated static files can be copied to any web server or CDN endpoint.

## 贡献指南

We welcome contributions from the community to improve YSLMitao, extend its functionality, and maintain the accuracy of the resource manifests. Please follow these steps to contribute effectively.

1. **Fork and Clone the Repository** – Create a personal fork of the project on GitHub, then clone your fork locally. Set up the upstream remote to track the main repository for syncing changes.

2. **Create a Feature Branch** – Use a descriptive branch name that reflects the nature of your contribution, such as `feature/add-csv-export-format` or `fix/health-check-timeout`. Avoid making changes directly on the main branch.

3. **Implement Changes with Tests** – Write your code following the existing shell script style (POSIX-compliant, with error handling) or Python conventions if extending the generator modules. Add corresponding tests in the `tests/` directory using the Bats framework for shell code or pytest for Python changes.

4. **Update Documentation** – Modify the relevant documentation files under `docs/` to reflect your changes, including any new command-line flags, configuration options, or manifest fields. Ensure the README quick start example still works as described.

5. **Submit a Pull Request** – Push your branch to your fork and open a pull request against the main repository's `develop` branch. Include a clear description of the changes, reference any related issues, and confirm that all CI checks pass. Pull requests with failing tests or missing documentation will not be merged.

## 常见问题

**Q: How does YSLMitao handle URL changes or redirects?**  
The health check script follows up to five redirects by default and records the final resolved URL in the status output. If a permanent redirect (HTTP 301 or 308) is detected, the script logs a warning and updates the cached final URL, but it does not automatically modify the manifest file. Administrators should review redirected entries periodically and update the manifest manually to avoid unnecessary redirection overhead. The differential comparison feature can highlight redirected entries by comparing the stored URL against the resolved URL.

**Q: Can I use YSLMitao with private or internal network resources?**  
Yes, the health check script respects the system's network configuration and proxy settings (via the `HTTP_PROXY` and `HTTPS_PROXY` environment variables). It supports HTTP and HTTPS protocols, as well as custom ports. For internal resources that require authentication, you can either disable the health check for those specific entries by adding the `skip_health: true` flag in the manifest, or use a custom wrapper script that injects authentication headers before invoking the check. The system does not include built-in credential management to keep the codebase minimal and secure.

**Q: What happens if the static site generator encounters a malformed URL?**  
The validation script (`validate.sh`) runs prior to the generation step and will exit with a non-zero code if any URL in the manifest fails basic syntax validation (e.g., missing protocol, invalid characters, empty string). The generator will not produce output until all manifest entries pass validation. This ensures that the generated dashboard never contains broken or malformed links. For edge cases such as internationalized domain names (IDN), the validation uses Python's `idna` library if available, falling back to a basic ASCII check otherwise.
