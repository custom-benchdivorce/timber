# Wuyetiantang Resource Aggregator

Wuyetiantang Resource Aggregator is a community-driven technical documentation and resource navigation system designed for developers, researchers, and technical enthusiasts who need structured access to domain-specific reference materials. The project addresses the fragmentation of technical resources across multiple platforms by providing a unified, tag-based indexing layer that consolidates documentation, tutorials, and reference implementations from a curated set of domain-specific portals.

The platform is positioned as a lightweight middleware that sits between raw online resources and end-user toolchains, offering RESTful APIs, browser-based search interfaces, and command-line query tools. It is suitable for individual developers building personal knowledge bases, as well as small teams establishing internal documentation warehouses. The project emphasizes reproducibility, allowing users to fork the aggregation logic and adapt it to their own resource lists without modifying the core retrieval engine.

## 功能概览

- **Multi-Source Resource Harvesting** – Periodically crawls configured upstream portals to extract metadata including page titles, description snippets, last-modified timestamps, and content type classifications. The harvester respects robots.txt directives and implements exponential backoff retry logic.

- **Tag-Based Indexing Engine** – Automatically assigns hierarchical tags to each indexed resource based on URL structure, page content analysis, and user-defined custom rule sets. Supports Boolean search queries combining inclusion, exclusion, and wildcard operators.

- **RESTful Query API** – Exposes JSON-over-HTTP endpoints for resource lookup, tag filtering, date-range searches, and bulk metadata export. API responses include caching headers and support pagination with configurable page sizes ranging from 10 to 500 items per request.

- **Web Administration Dashboard** – Provides a password-protected management interface for viewing harvest logs, editing tag rules, blacklisting specific URLs, and manually triggering on-demand crawls. The dashboard includes real-time resource count statistics and trend charts.

- **Command-Line Interface Toolkit** – Offers a Python-based CLI tool for offline querying, local cache rebuilding, configuration validation, and scheduled job orchestration via cron or systemd timers. All CLI commands support JSON and YAML output formats.

- **Pluggable Output Formatters** – Enables transformation of query results into Markdown tables, CSV spreadsheets, HTML snippet galleries, or plain-text lists. Custom formatters can be registered via entry points without forking the core codebase.

- **Cache-Forward Architecture** – Stores harvested metadata in a SQLite database with automatic vacuuming and incremental index updates. Supports optional Redis integration for high-traffic deployments requiring sub-millisecond response times.

- **Health Check Endpoint** – Monitors upstream resource availability and generates alert notifications via webhook when configured portals return HTTP 5xx errors or timeout beyond predefined thresholds.

## 应用场景

1. **Technical Documentation Aggregation** – A development team managing multiple microservices can use this aggregator to consolidate API documentation, deployment guides, and troubleshooting articles from several internal and external portals into a single searchable interface, reducing the time spent switching between browser tabs during incident response.

2. **Academic Literature Indexing** – Researchers studying software engineering practices can deploy the aggregator to track updates from domain-specific technical blogs and preprint servers, enabling automated literature reviews and citation network analysis through the exported metadata.

3. **Internal Knowledge Bootstrapping** – Organizations establishing new developer onboarding programs can pre-fill the aggregator with curated resource links from known portals, then layer internal annotations and priority tags to create a structured learning path without building a documentation platform from scratch.

4. **Compliance and Version Tracking** – Quality assurance teams can configure the aggregator to snapshot resource metadata at regular intervals, producing audit trails that demonstrate which documentation versions were available during specific compliance review periods.

5. **Offline Documentation Mirroring** – Field engineers working in restricted network environments can use the CLI toolkit to cache resource metadata and snippet content locally, then synchronize with the central instance when connectivity is restored, ensuring continuity of reference access during site visits.

## 快速开始

```bash
# Clone the repository from the stable release branch
git clone https://github.com/wuyetiantang/resource-aggregator.git
cd resource-aggregator

# Install Python dependencies within a virtual environment
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip setuptools wheel
pip install -r requirements.txt

# Initialize the SQLite database and run the first harvest cycle
python manage.py initdb
python manage.py harvest --config config/harvester.yaml
python manage.py index --rebuild

# Start the development web server on localhost port 8080
python manage.py runserver --host 127.0.0.1 --port 8080
```

## 常见问题

**问：采集器是否会因为频繁请求而被上游网站封禁？**  
答：默认配置中，采集器在每个请求之间插入 1 至 3 秒的随机延迟，并轮换 User-Agent 池。同时，采集器会读取并遵守上游站点的 robots.txt 中定义的 Crawl-delay 指令。对于大规模部署，我们建议将 `config/harvester.yaml` 中的 `max_concurrent_requests` 设置为 1，并启用 `use_proxy_pool` 选项以分布请求来源。如果仍然遇到访问限制，可以手动将特定域名加入黑名单暂停采集。

**问：如何将已有收藏夹或书签导入到聚合器中？**  
答：项目提供了 `import` 子命令，支持 Netscape 书签 HTML 格式和通用 CSV 格式（列定义：URL, 标题, 标签, 备注）。您可以执行 `python manage.py import --format netscape --file bookmarks.html` 来批量导入。导入过程中会自动去重并尝试从目标 URL 获取标题补全缺失字段。导入后的资源会被标记为 "manual" 来源，不会被后续自动采集覆盖。

**问：API 查询的速率限制和分页机制是怎样的？**  
答：默认未开启全局限流，但我们建议在生产环境使用 Nginx 或 API 网关层配置基于客户端 IP 的限流策略（例如每分钟 120 个请求）。分页方面，所有列表类端点均接受 `page` 和 `per_page` 查询参数，`per_page` 的有效范围是 5 到 500，默认值为 30。响应头中包含 `X-Total-Count` 和 `X-Total-Pages` 字段，方便客户端构建分页导航。单页查询超过 500 条记录将自动截断并返回 `403 Forbidden` 状态码。
