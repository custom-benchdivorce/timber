# Wuyetiantang Resource Hub

Wuyetiantang Resource Hub is a community-driven navigation and resource aggregation platform designed for technical researchers, content archivists, and digital resource analysts who require structured access to specialized online repositories. The project addresses the critical need for organized, maintainable, and rapidly deployable reference indices that consolidate distributed web resources into a single, queryable catalog.

Target users include system administrators building internal knowledge bases, data engineers constructing ETL pipelines from heterogeneous web sources, and academic researchers conducting longitudinal studies of digital content ecosystems. By providing a standardized metadata framework and lightweight retrieval interface, the hub reduces discovery friction and enables reproducible resource tracking across distributed teams.

## 功能概览

- **Structured Resource Cataloging** – Organizes external URLs into semantically tagged categories with versioned metadata, supporting both manual curation and automated ingestion workflows.

- **Regex-Based Query Routing** – Implements pattern-matching dispatch logic that maps user search tokens to predefined resource clusters, enabling rapid subset retrieval without full-text indexing overhead.

- **Markdown-Generated Static Site** – Compiles the entire resource index into a deployable static document tree using pure Markdown, eliminating database dependencies and simplifying mirroring.

- **Dependency-Free Local Server** – Serves the catalog via a built-in Python HTTP module or Node.js `serve` utility, requiring zero additional runtime frameworks for basic operation.

- **Periodic Update Hooks** – Provides shell script stubs for cron-driven synchronization tasks, allowing administrators to refresh external link validity and metadata timestamps automatically.

- **Accessibility Compliance Layer** – Enforces contrast ratios, semantic heading structures, and ARIA label stubs in generated HTML outputs to accommodate screen reader users in enterprise deployments.

- **Pluggable Output Formatters** – Supports JSON, CSV, and plain-text export formats alongside Markdown, facilitating integration with monitoring dashboards and data warehousing pipelines.

- **Audit Logging** – Records timestamped access events and query patterns to a rotating flat-file log, supporting basic usage analytics and anomaly detection.

## 应用场景

- **Enterprise Internal Knowledge Portal** – Organizations can deploy the hub as an intranet start page, aggregating links to internal documentation, JIRA instances, Confluence spaces, and CI/CD dashboards. The flat-file architecture ensures compatibility with air-gapped environments where database servers are prohibited.

- **Academic Literature Curation** – Research groups studying digital media trends can use the catalog to maintain longitudinal reference sets of domain-specific resources. The version-controlled Markdown files integrate seamlessly with Git-based collaboration workflows for peer review of resource inclusion.

- **DevOps Monitoring Aggregator** – Site reliability engineers can populate the hub with status dashboards, log viewers, and metric explorer URLs for multiple environments. The regex routing feature enables quick context switching between production, staging, and development namespaces using simple query aliases.

- **Training Lab Environment** – Educators conducting web technology workshops can preload the resource list into student VMs, providing a controlled starting point for exercises in web scraping, API consumption, and content analysis without requiring students to manually discover seed URLs.

- **Personal Bookmark Archival** – Individual power users can replace browser bookmark sprawl with a self-hosted, plain-text index that remains readable and editable across operating systems, with optional encryption via standard filesystem tools.

## 快速开始

Clone the repository, install the lightweight runtime dependencies, and launch the local preview server with the following commands:

```bash
# Clone the project repository
git clone https://github.com/wuyetiantang/resource-hub.git
cd resource-hub

# Install required utilities (Python 3 + pip)
pip install --user markdown pyyaml

# Generate the static site from source Markdown
python build.py --input ./catalog --output ./dist

# Start the local development server on port 8080
python -m http.server 8080 --directory ./dist
```

For production deployment, replace the Python HTTP server with Nginx or Apache using the provided `nginx.conf` sample. The static output directory `./dist` contains all generated HTML assets and can be copied directly to any web server document root.

## 常见问题

**Q: How does the hub handle external URL changes or link rot?**

The project does not automatically redirect or rewrite external URLs. However, the included `scripts/check-links.sh` utility performs periodic HEAD requests to test reachability. If a link repeatedly fails, the maintainers may flag it as `[deprecated]` in the catalog metadata. Administrators can also override this behavior by setting `allow_unreachable: true` in the per-entry YAML frontmatter, which suppresses validation warnings during the build process.

**Q: Can I deploy this behind a corporate firewall with no internet access?**

Yes. The build process only requires the local source files and the Python dependencies listed in the installation table. Once the initial `pip install` is completed, no external network calls are made during the build or serving phases. The optional link-checking script is the only component that performs outbound requests, and it can be disabled by omitting it from your cron schedule. The static output in `./dist` is fully self-contained and can be transferred to isolated networks via USB drive or internal artifact repositories.

**Q: How do I customize the visual theme beyond the default dark/light toggle?**

The default theme is defined in `static/css/custom.css`. You can override any CSS variable declared in the `:root` selector by creating a `static/css/overrides.css` file and uncommenting the include line in `templates/base.html`. For more extensive changes, we recommend forking the repository and modifying the base template directly. The project does not provide a formal theming API, but the CSS architecture uses BEM-like class naming to simplify selective overrides without breaking layout integrity.
