# Nebula Resource Gateway

Nebula Resource Gateway is a lightweight, high-performance metadata aggregation and navigation system designed for technical content curation, external resource indexing, and structured documentation management. It targets developers, technical writers, and open-source maintainers who need to catalog, verify, and present large volumes of external links with strict formatting controls and versioned documentation pipelines.

The project solves the problem of chaotic link collection and inconsistent presentation in technical repositories by providing a standardized, modular framework that enforces URL integrity, separates presentation from data, and enables automated validation of external resources. It is not a search engine, nor a general-purpose bookmark manager—it is a disciplined gateway layer for curated technical ecosystems.

## 功能概览

- **Strict URL Passthrough Engine** – Preserves every character of user-supplied URLs, including protocol, subdomain, trailing slashes, and case, with zero normalization or auto-correction, ensuring legal and brand compliance.

- **Markdown-First Document Pipeline** – Renders all navigation structures, resource lists, and system metadata as pure Markdown with mandatory code-block wrapping for URLs, eliminating accidental linkification or formatting drift.

- **Modular Section Templating** – Provides fixed-order, required-section templates (overview, features, scenarios, quickstart, requirements, docs, resources, structure, contributions, faq, license) that enforce completeness and consistency across multilingual documentation suites.

- **Batch Resource Management** – Supports multi-batch input processing (current batch 12/34) with per-item audit trails, allowing maintainers to track which URLs have been validated, deprecated, or updated across release cycles.

- **ASCII Directory Tree Visualizer** – Auto-generates annotated directory trees from the project root, including hidden configuration files, test fixtures, and build artifacts, with inline commentary for each node.

- **Dependency and Environment Table Generator** – Extracts runtime requirements, build tools, and optional components from pyproject.toml or package.json and presents them as a sortable Markdown table with mandatory version constraints.

- **Contribution Workflow Enforcer** – Defines a four-step contribution lifecycle (fork, branch, commit, pull request) with pre-commit hook examples and commit message conventions, reducing maintainer overhead.

- **FAQ Knowledge Base** – Built-in question-and-answer engine that maps common user issues (URL formatting, build failures, batch processing errors) to actionable resolutions without external dependencies.

## 应用场景

- **Technical Documentation Portals** – Project maintainers can use Nebula Resource Gateway to structure external reference links, API documentation endpoints, and third-party toolchains within a unified Markdown repository, ensuring that every hyperlink is preserved exactly as specified by legal or compliance teams.

- **Open-Source Curation Projects** – Curators managing large collections of domain-specific resources (e.g., free image datasets, academic paper repositories, code snippet archives) can leverage the batch resource management and strict URL passthrough to maintain audit-ready link catalogs across multiple release batches.

- **Internal Developer Platform Wikis** – Platform engineering teams can deploy the gateway as a documentation frontend for internal tooling, where every external dependency URL, internal service endpoint, and configuration reference must be frozen in version control with immutable formatting rules.

- **Regulated Industry Documentation** – In sectors with strict URL branding and trademark requirements (e.g., financial services, healthcare), the project ensures that all displayed URLs match the exact string approved by legal, preventing accidental redirection or protocol upgrades that could violate compliance policies.

- **Educational Resource Repositories** – Educators and curriculum developers can organize course materials, lab guides, and external reading lists with deterministic formatting, allowing students to copy-paste URLs directly from the documentation without transformation errors.

## 快速开始

```bash
# Clone the repository
git clone https://github.com/nebula-gateway/nebula-resource-gateway.git
cd nebula-resource-gateway

# Install dependencies using pip for Python version 3.9+
pip install -r requirements.txt

# Run the gateway build pipeline to generate the final README and resource index
python build_gateway.py --batch 12 --input ./batches/batch_12.json --output ./dist/README.md
```

## 贡献指南

1.  **Fork the Repository and Set Up Development Environment** – Fork the main repository on GitHub, clone your fork locally, and create a new virtual environment with Python 3.9+. Install all development dependencies using `pip install -r requirements.txt` and pre-commit hooks via `pre-commit install`.

2.  **Create a Feature Branch with a Descriptive Name** – Branch from the latest `main` branch using a name that reflects your change, such as `feature/batch-13-validation` or `fix/url-passthrough-case-sensitivity`. Avoid making changes directly on the `main` branch.

3.  **Implement Changes with Comprehensive Tests** – Add or modify code under `src/` and write corresponding test cases under `tests/`. Ensure that all existing tests pass and that your new code includes both positive and negative test coverage. Update the relevant documentation in `docs/` if your changes affect user-facing behavior.

4.  **Commit with Semantic Messages and Submit a Pull Request** – Commit your changes using the conventional commit format: `<type>(<scope>): <subject>`. For example, `feat(validator): add case-preservation for domain labels`. Push your branch to your fork and open a pull request against the main repository's `main` branch. Describe your changes, reference any related issues, and request a review from at least one maintainer.

## 常见问题

**Q: Why does the project enforce strict URL formatting without adding or removing protocols? Why can't I use markdown link syntax like [text](url) for resource listing?**

A: The gateway is designed for legal, compliance, and brand-protection scenarios where the exact string representation of a URL must be preserved as provided by the source. Many organizations have trademark, copyright, or regulatory requirements that forbid automatic protocol upgrades (e.g., changing HTTP to HTTPS) or adding www prefixes. Using `<code>` tags instead of markdown links prevents browsers and parsers from applying auto-linkification or redirection heuristics, ensuring that users see the exact URL they are expected to use. If you need clickable links, you can still copy the code-block content and paste it into your browser's address bar.

**Q: How do I add a new batch of URLs beyond batch 12? What is the JSON schema for batch files?**

A: Create a new JSON file under `batches/` with the naming convention `batch_XX.json` where XX is the batch number. Each batch file must contain a JSON array of objects, with each object having the following fields: `"url"` (string, required), `"category"` (string, optional), `"description"` (string, optional), and `"status"` (string, enum: active/deprecated/pending). The gateway validates that each `"url"` is unique within the batch and that it is not an empty string. After creating the file, run `python build_gateway.py --batch XX --input ./batches/batch_XX.json --output ./dist/README.md` to regenerate the documentation. Ensure that your batch number is sequential and does not skip existing batches to maintain proper audit trails.

**Q: The ASCII directory tree does not show some of my files or directories. How do I control which entries are included?**

A: The tree generator respects a `.treeignore` file at the project root, which uses the same syntax as `.gitignore`. By default, it excludes `__pycache__/`, `*.pyc`, `.pytest_cache/`, `dist/`, and `logs/`. To include a specific file or directory, ensure it is not matched by any pattern in `.treeignore`. You can also modify the `IGNORE_PATTERNS` list in `src/tree_generator.py` if you need project-wide overrides. If you want to add inline annotations for specific nodes, you can create a `.tree_annotations` file in the same directory as the tree generator, mapping paths to annotation strings.
