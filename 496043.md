# Wuyetiantang Resource Aggregator

Wuyetiantang Resource Aggregator is a curated technical index and navigation system designed for developers, researchers, and content archivists who need systematic access to distributed online resources. The project addresses the common challenge of managing disparate domain-based information sources by providing a unified query interface, structured metadata tagging, and automated availability monitoring for a predefined set of resource domains.

Target users include system administrators maintaining content mirrors, academic researchers conducting longitudinal web studies, and DevOps engineers building automated data pipelines that depend on stable external resource endpoints. The aggregator does not host or redistribute any third-party content; it functions strictly as a discovery and health-check layer over user-provided domain lists.

## 功能概览

- **Domain Health Monitoring** – Periodic HTTP/HTTPS reachability checks for each registered domain with response time histograms and SSL certificate expiry warnings.

- **Metadata Tagging Engine** – User-assignable labels (e.g., "video", "forum", "archive", "mirror") per domain with full-text search over tags and descriptions.

- **Unified Query Gateway** – Single API endpoint that accepts category filters and returns sorted domain lists with last-seen status and content-type hints.

- **Automated Change Detection** – Diff-based alerting when a domain's landing page title or meta description changes beyond a configurable threshold.

- **Exportable Inventory Reports** – Generate JSON, CSV, or plain-text snapshots of the current domain registry for offline use or backup.

- **Historical Uptime Logging** – Store daily reachability results in a lightweight SQLite database with retention policies and pruning strategies.

- **Custom Redirect Rules** – Define per-domain rewrite rules (path-based or query-based) to handle common URL structure variations without modifying upstream sources.

## 应用场景

- **Content Mirror Orchestration** – Operators managing regional mirrors of popular online libraries can use the aggregator to verify that all source domains remain accessible before triggering scheduled rsync or wget jobs.

- **Academic Data Collection** – Researchers conducting longitudinal studies of Chinese-language online communities can maintain a stable domain registry and receive notifications when any site changes its availability pattern, helping to correlate with network policy shifts.

- **Automated Documentation Generation** – Technical writers maintaining external link sections in large project manuals can embed the aggregator's API to dynamically render up-to-date domain lists, ensuring that printed or static documentation never points to dead endpoints.

- **DevOps Pipeline Health Checks** – CI/CD pipelines can pre-flight external resource dependencies by querying the aggregator's /health endpoint, failing early if any required domain is unreachable, thus avoiding flaky integration test failures.

## 快速开始

```bash
# Clone the repository
git clone https://github.com/wuyetiantang/aggregator.git
cd aggregator

# Install dependencies (Python 3.9+ required)
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
pip install -r requirements.txt

# Initialize the local database and load default domain list
python manage.py init-db
python manage.py load-domains --source config/domains.default.json

# Start the development server
python manage.py runserver --host 0.0.0.0 --port 8080
```

After startup, access the web interface at http://localhost:8080/dashboard. The default admin credentials are printed to the console during first initialization.

## 贡献指南

We welcome contributions that improve reliability, extensibility, or documentation clarity. Follow the steps below to submit a change.

1. Fork the repository and create a feature branch from `main` with a descriptive name, such as `feature/add-icmp-checker` or `fix/scheduler-timezone-bug`.

2. Write or update unit tests for any modified code in the `tests/unit/` directory. Ensure all existing tests pass by running `pytest --cov=src` before committing. New features must maintain at least 85% line coverage.

3. Update the relevant documentation sections in `/docs/` to reflect your changes. For API modifications, regenerate the OpenAPI schema using `python manage.py generate-openapi` and commit the updated `openapi.json`.

4. Submit a pull request against the `main` branch with a clear description of the problem, your solution, and any manual testing performed. Include screenshots for UI changes or sample API responses for backend changes.

5. Wait for the continuous integration workflow to complete. All checks must pass before a maintainer will review your submission. Address review comments promptly; stale pull requests are closed after 14 days of inactivity.

## 常见问题

**Q: How does the aggregator handle domains that return HTTP 403 or require Cloudflare CAPTCHA?**

A: The health checker treats any non-2xx or non-3xx status as "unreachable" unless explicitly configured via the `--allow-status` flag. For CAPTCHA-protected sites, the system cannot validate content semantics, but it still records the HTTP status and response time. Users are advised to configure custom redirect rules or alternate ports for such endpoints. The aggregator does not attempt to solve CAPTCHAs or simulate browser behavior beyond standard HTTP GET requests with a common User-Agent header.

**Q: Can I run the aggregator behind a corporate firewall that restricts outbound traffic?**

A: Yes. Set the `HTTP_PROXY` and `HTTPS_PROXY` environment variables before starting the server. The checker respects these variables for all outbound requests. Additionally, you can define a per-domain proxy override in the `config/domains.default.json` file by adding a `"proxy"` field. If your network requires custom CA certificates, place the PEM file at `config/custom-ca.pem` and reference it in the `SSL_CERT_FILE` environment variable.

**Q: How do I migrate the SQLite database from one machine to another without losing historical data?**

A: Stop the running server, copy the `aggregator.db` file located in the `data/` directory to the new machine, and place it in the same relative path. Then run `python manage.py migrate` to ensure the schema matches the current version. If the target machine has a different architecture (e.g., ARM vs x86), the SQLite file is fully portable – no conversion is needed. For incremental sync, use the built-in export/import commands: `python manage.py export --format json > backup.json` and `python manage.py import backup.json`.
